Based on the Java 25 / Spring Boot 4.1 source tree and the PostgreSQL adapter implementation.

A local engine for job search work.

Job Engine is a Model Context Protocol server that turns candidate profiles and job postings into normalized, searchable records; creates explainable match reports; and generates tailored application documents.

JAVA 25SPRING BOOT 4.1SPRING AI MCPPOSTGRESQLFLYWAY
Important: this application is a local backend. It is not a public website, REST API, hosted service, or job-board scraper. Clients such as Hermes connect to its loopback-only MCP endpoint.
01 / CAPABILITIES

What the application does

The feature set follows a job-application lifecycle, from capturing source information through evaluation and document generation.

PROFILE / 01

Normalized candidate profiles

Create, search, read, replace, and delete profiles with contacts, links, skills, languages, education, experience, projects, and project technologies. Revision checks prevent accidental lost updates.

INGEST / 02

PDF storage and ingestion

Store document bytes in PostgreSQL, extract bounded PDF text, and deterministically map a stored resume into the normalized profile schema while preserving its source link.

JOBS / 03

Job capture and search

Insert jobs from pasted text or a tightly restricted URL flow, deduplicate by source identity and canonical fingerprint, search weighted fields, and maintain normalized skills and provenance.

MATCH / 04

Explainable deterministic matching

Score profile–job pairs across technical fit, experience and seniority, domain, delivery, and hard requirements. Evidence, confidence, staleness, reviews, and disagreements remain inspectable.

OUTPUT / 05

Resume generation

Generate and persist master, Canadian English, Canadian French, and tailored bilingual German resume PDFs from normalized profile data.

LETTER / 06

German cover letters

Create a deterministic German cover letter from a current Germany-format resume, profile, and job; persist structured content and a PDF while returning metadata only over MCP.

SEARCH / 07

Bounded, deterministic search

Profiles and jobs use normalized indexed terms, weighted fields, strict query and candidate limits, stable ordering, and explicit truncation signals.

OPS / 08

Health and cleanup

Report database readiness and sanitized generated-file cleanup health. Scheduled cleanup removes generated files safely and retains bounded audit history.

02 / RUNTIME FLOW

How a request moves through the system

Every MCP operation follows the same basic route. Protocol details stay at the edge; business rules stay in application and domain code.

Client calls an MCP tool

A local MCP client sends a structured tool request to http://127.0.0.1:8080/mcp using Streamable HTTP.

Inbound adapter translates the request

A class under adapter/in/mcp validates the object shape, converts it to an application request, and maps failures to safe structured errors.

Application service orchestrates the use case

The service applies canonicalization, validation, idempotency, transaction boundaries, pagination rules, and calls domain logic through ports.

Domain code makes deterministic decisions

Pure Java aggregates and policies compute fingerprints, scores, evidence, variants, and invariants without depending on Spring, MCP, or JDBC.

Outbound adapter handles infrastructure

PostgreSQL repositories persist aggregates with JDBC; other adapters fetch approved HTTP content, extract PDFs, write generated files, or provide optional analysis.

Structured result returns to the client

The adapter returns normalized application data. Sensitive raw text, binaries, credentials, private URLs, prompts, and reasoning traces are deliberately omitted where required.

05 / SOURCE SPOTLIGHT

Inside PostgresJobRepository

PostgresJobRepository implements the application’s JobRepository port. It is the persistence boundary for job aggregates—not the place where MCP or high-level use-case decisions live.

Aggregate storage

A job aggregate combines a JobPosting, ordered JobSkill rows, and exactly one ingestion provenance form: link or pasted text. Reads hydrate these pieces in bounded batch queries; writes update them transactionally.

jobs
↳ job_skills
↳ job_link_ingestions or job_text_ingestions
↳ search_terms

Snapshot keyset pagination

Pages are fixed to a snapshot timestamp and continue by created_at + id, avoiding offset drift as new jobs arrive.

Optimistic concurrency

Updates include WHERE revision = :expectedRevision. A stale writer changes zero rows instead of silently overwriting newer data.

Idempotent insertion

Unique normalized URLs, input-text hashes, and canonical fingerprints converge duplicate requests onto the existing aggregate.

Transactional index maintenance

Skills and weighted search terms are replaced or rebuilt in the same transaction as the job mutation.

How job search works

1 · NORMALIZEQuery termsThe application constrains query length and token count, then normalizes tokens and prefixes.
2 · LOOK UPIndexed postingsSQL searches job_schema.search_terms by exact/prefix ranges with strict per-token bounds.
3 · SCOREWeighted hitsTitle = 8, skill = 7, company = 5, experience = 4, location/description = 3, employment/seniority = 2.
4 · BOUNDCandidate capThe repository returns at most 500 candidates and signals when postings or candidate results were truncated.
5 · HYDRATEFull aggregatesCandidate jobs receive ordered skills and sanitized ingestion provenance before application-level final ranking.
Privacy detail: pasted job text is represented by a hash for source identity; it is not stored raw in the method-specific text-ingestion table. Link provenance is redacted by the application’s ingestion policy before it becomes MCP-visible.
06 / EXPLAINABILITY

Deterministic match analysis

Matching produces an immutable baseline that can be reproduced and audited. Optional advisory reviews never replace it.

40 POINTS

Technical fit

Compares normalized job skills against profile skills and technologies, retaining evidence for the component score.

25 POINTS

Experience & seniority

Uses structured experience and seniority data. Missing evidence stays unknown rather than becoming a guessed mismatch.

15 + 10

Domain & delivery

Separately represents domain relevance and delivery evidence so the report shows where confidence comes from.

10 POINTS

Hard requirements

Tracks blocker evidence explicitly. A skill’s required flag by itself is not sufficient blocker provenance.

Known evidence is normalized into an outcome while unknown evidence lowers confidence. Reports also record source revisions, so reads can show when a profile or job has changed since analysis. Divergence policy can create deduplicated disagreement records when an advisory review differs materially.

07 / DOCUMENT PIPELINE

From profile data to application PDFs

Document workflows separate normalized content, rendering, database storage, runtime files, and cleanup.

Load current source aggregates

Resume generation reads the normalized profile; tailored workflows also read the job and current revisioned source records.

Build and review structured content

Pure application builders select, order, cap, and translate content deterministically. German and French variants use offline Java translation.

Render ATS-safe PDFs

Renderers create compact one-column documents with bounded text and predictable A4-oriented output.

Persist metadata and bytes

Generated PDFs are stored as documents and linked to the relevant profile, resume, job, language, format, and variant.

Manage runtime assets

Generated filesystem paths are returned as metadata where appropriate. Replacement/deletion schedules safe post-transaction file cleanup with retained audit rows.

08 / SAFETY

Local-first security boundaries

  • MCP is published only on host loopback; PostgreSQL is not published.
  • A startup guard rejects unsafe MCP transport and bind combinations.
  • Local file imports are restricted to a configured import root.
  • Document metadata endpoints do not return stored binary content.
  • URL fetching rejects redirects, userinfo, local/private/metadata targets, and hostnames.
  • Structured errors avoid leaking credentials, paths, or provider internals.
  • Pagination cursors are integrity-protected and opaque to callers.
  • Flyway owns ordered, versioned schema changes.
09 / OPERATIONS

Run and verify locally

Docker Compose is the normal development path. The persistent server uses Streamable HTTP; STDIO is reserved for CI and isolated diagnostics.

# Build and start PostgreSQL + MCP
docker compose up -d --build --wait postgres mcp

# Verify initialization, tool discovery, and health
python3 scripts/smoke-mcp-http.py

# Supported local endpoint
http://127.0.0.1:8080/mcp

For host-side development, ./mvnw test runs unit tests and ./mvnw verify -Pintegration-tests runs Docker-backed integration tests through Failsafe. Java 25 is required when Maven runs on the host.
